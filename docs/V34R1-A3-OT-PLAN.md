# A3 OT: source-track HOTA guard on separate MOT17 DEV sequences

The [frozen OT protocol](../configs/v34r1-a3-ot-probe.json) defines this separate component experiment. It does not change A2 results or the in-flight OD probe. The [source reservation](V34R1-A3-OT-SOURCES.md) defines64 contiguous frames per FIT/validation sequence, with no shared physical video across splits. Only source SHA/cached metadata is prepared for reserved TEST; this DEV job never extracts its pixels.

The previous guard measured missed/extra boxes and identity switches at IoU.5. The new hypotheses use the pinned official HOTA implementation on **observed source tracks as pseudo reference**, over the observed prefix or trailing32 frames. They are not GT HOTA guarantees. HOTA/DetA/AssA damage must each stay within one FIT-selected excess limit relative to an identity trial from the same committed decoded history. Candidate trials clone that past; only the chosen trial commits, and state resets per physical sequence. Source and receiver ByteTrack use original seqinfo14/25/30fps. The codec also uses native cadence. This differs from the older MOT20 experiment at25fps; comparisons inside this experiment use the same native-cadence identity/A2 guard.

Cache exactly the A2 controller shortlist and fixed OT profiles13/16/17/19 at QP30/35/40/45, both codecs. Every packet uses medium/closedGOP16 and pays complete headers; every receiver prediction follows real decoding. No extra profile bank or low-confidence mask change is included, isolating the source-proxy change. Original clean/decoded detections are cached once and reused by causal policy replays, without repeating codec trials.

FIT tests the predeclared six limits independently for observed-prefix and trailing32 guards. Choose using official combined-sequence GT HOTA: mean drop<=.002 absolute and each codec/QP drop<=.01 against identity, then lowest mean per-window log paid-byte ratio, smaller-limit tie break, identity fallback. Save the policies before scoring the two validation sequences. Preserve all four raw points and undefined/nonmonotone BD. Reserved3-sequence TEST can be evaluated only for a frozen policy passing both validation BD endpoints strictly below−15%; no validation retuning.
